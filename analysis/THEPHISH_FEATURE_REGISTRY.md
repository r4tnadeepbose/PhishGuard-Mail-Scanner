## 2. Capability areas (as discovered)

1. **Email ingestion:** IMAP unread retrieval, EML-attached submission discovery (`F-ING-*`).
2. **Email/MIME parsing:** internal EML extraction, header/body/attachment parsing (`F-PARSE-*`).
3. **IOC extraction & normalization:** URL/domain/IP/mail extraction, basic cleanup (`F-IOC-001`).
4. **Whitelisting:** exact/regex/domain-context suppression (`F-WL-001`).
5. **Threat intelligence/analyzers:** Cortex analyzer execution and specialized handlers (`F-ORCH-*`, `F-NORM-001`).
6. **Verdict generation:** count-based malicious/suspicious/safe classification (`F-VER-001`).
7. **Case/task management:** TheHive template/case/observable/task lifecycle (`F-CASE-*`).
8. **IOC classification/export:** mark IOC and MISP export on malicious verdict (`F-VER-001`, `F-MISP-001`).
9. **Notifications:** Mailer responder start/verdict emails (`F-NOTIF-001`).
10. **Realtime monitoring/UI:** Flask web UI + Socket.IO logs (`F-UI-001`, `F-LOG-001`).
11. **Configuration/logging/deployment:** JSON configs and Docker stack (`F-CFG-001`, `F-DEP-001`).

## 3. Explicit non-findings / cautions

- No built-in local phishing heuristics/ML engine equivalent to PhishGuard's scanner was identified; detection is delegated to external analyzers and simple aggregation.
- No native persistent investigation database, timeline model, or evidence-hash chain inside ThePhish app was identified.
- No authentication/authorization, CSRF protection, or granular RBAC in the Flask app was identified.
- No first-class support for IPv6, file-content sandboxing, or advanced header authentication verification (beyond analyzer outputs) was identified in app code.
